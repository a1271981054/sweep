# Sweep 磁盘清理

把开源项目 [Sweep](https://github.com/iliyami/Sweep) 的扫描引擎（`MacCleanKit`）包装成本地 MCP 服务器，让 agent 能读磁盘、找垃圾、并在**你批准之后**清理。

## 工具

| 工具 | 作用 | 会删东西吗 |
|---|---|---|
| `disk_report` | 数据卷总量、已用、可用 | 否 |
| `scan_start` / `scan_status` | 异步扫描：系统垃圾（21 类）、项目垃圾、大文件、旧文件、重复文件 | 否 |
| `scan_large_files` | 指定根目录下最大的用户文件 | 否 |
| `scan_old_files` | 指定天数未修改的用户文件 | 否 |
| `scan_duplicates` | 字节级相同的副本（体积 → 部分哈希 → 全量 SHA-256） | 否 |
| `plan_clean` | 用快照 + 选中的 id 生成清理计划与摘要 | 否 |
| `apply_clean` | 摘要匹配后把计划内项目移入废纸篓 | **是**（可还原） |
| `restore_clean` | 按操作日志把移走的项目放回原处 | 否（只还原） |
| `list_operations` | 最近的清理记录 | 否 |
| `render_chart` | 把扫描或清理计划渲染成图片返回（带 digest） | 否 |

## 安全模型

1. **只认 id**：扫描产出快照，候选带稳定 id。`plan_clean` 只接受 id，绝不接受裸路径，因此文件名里的指令无法变成删除目标。
2. **摘要校验**：`apply_clean` 必须回传 `plan_clean` 给出的摘要；期间文件大小或路径变化会让摘要失效，计划作废。
3. **废纸篓优先**：删除即移动到废纸篓，`restore_clean` 可放回；永久删除不在本工具范围内。注意移入废纸篓不会立刻释放磁盘空间，清空废纸篓后才真正回收，但那时也就无法还原了。
4. **受保护路径**：`~/Documents`、`~/Desktop`、`~/Pictures`、`.git`、`.ssh`、钥匙串等在代码里硬拒。
5. **预算上限**：单次操作有体积与条数上限，超限直接拒绝执行。
6. **审计**：每次执行写入 `~/.sweep/operations.jsonl`，含摘要、路径、字节数与结果。

## 三种自主度

配置文件 `~/.sweep/config.json` 的 `mode`：

| mode | 行为 |
|---|---|
| `readonly` | 只有 `scan_*` 与 `disk_report` 可用，`apply_clean` 直接报错 |
| `confirm`（默认） | 必须提供与计划一致的摘要才能执行 |
| `auto` | 允许对白名单分类（缓存/日志/包管理器）自动执行，仍受体积与条数预算约束 |

## 需要的权限

完全磁盘访问权限（Full Disk Access）能显著扩大可扫描范围：`~/Library/Mail`、`Safari`、`Messages` 与部分系统缓存没有它会被跳过。被跳过的根目录会出现在结果的 `deniedPaths` 里，并附 `hint` 提示——那说明结果不完整，而不是「没有可清理项」。

## 限制

- 只清理当前用户空间。`/Library` 下的系统级缓存与需要 root 的项目不会被处理。
- 大文件、旧文件、重复文件属于你自己的文件，不会被任何自动模式清理。
- 扫描是同步调用；系统垃圾在百万级文件时可能需要数十秒，客户端超时请调大或分模块扫描。
